教室大屏「正在播放」叠加层 — 开发者说明

VoiceHubComponent（ClassIsland 校园广播站点歌排期插件）· 新增功能的技术记录

核心约束 只读叠加层：把服务端音乐管理员的权威广播状态实时显示到当日排期卡片，不写任何数据。新增字段均为新增读取，不改动任何既有字段名 / 接口路径；未升级 ClassIsland.PluginSdk、未引入新 NuGet 依赖。

一、实现概览

新增一条独立后台通道专门拉取播控状态，与既有的主刷新（排期 + 歌词刷新）完全解耦，互不干扰：

  • 拉取：Services/BroadcastStateClient.cs 后台线程，SSE（GET /api/music/websocket，事件 broadcast_state）为主，GET /api/music/broadcast 每 30s 轮询兜底；断线指数退避重连（1s→2s→4s…封顶 30s）。
  • 匹配：广播快照的 scheduleId 命中当前卡片的 SongItem.Id；缺失时退化为 songId + playDate 同配。
  • 渲染：命中且正在播放时，在 NowPlayingPanel 第二行叠加脉动徽标 / 进度条 / 接下来 / 在线人数；停播、掉线（>95s 无快照）、不匹配时完全不显示，界面与改动前一致。
  • 进度：本地每秒外推 position，仅偶尔快照纠偏，绝不每秒发请求。

二、数据契约（仅新增读取）

插件只读下列字段，不发送任何写请求。后端对接或改动接口时按此对齐。

2.1 排期接口 GET /api/songs/public（逐条）

新增字段类型说明
isPlayingbool该排期项是否正在播放；老服务端无此字段默认 false（天然兼容）。
broadcastPositiondouble?已播秒数；无则 null。

2.2 广播接口 GET /api/music/broadcast 与 SSE broadcast_state

字段（位于 broadcast 对象内）类型说明
scheduleIdint?排期 id，精确匹配首选；null 时退化匹配。
songIdint歌曲 id，退化匹配用。
playDatestring?播放日期 yyyy-MM-dd，退化匹配用。
titlestring?曲目标题。
durationdouble总时长（秒）。
positiondouble当前进度（秒）。
isPlayingbool是否播放中。
nextUp.{songId,title,duration}obj下一首信息；broadcast 为 null 表示无广播。
根级 listeners / baselineReleasedint / bool在线人数 / 基准播控人是否掉线释放。

三、命中匹配逻辑

  1. 收到广播快照且 broadcast != null。
  2. scheduleId 有值 → 与当前卡片 SongItem.Id 精确比较（同日同曲可能排两次，必须精确）。命中则显示叠加层。
  3. scheduleId 为 null → 退化为 songId + playDate 同配。
  4. 都不匹配 → 不显示（保持原界面）。

四、UI 状态一览

场景叠加层表现
无广播 / 停播（broadcast=null）完全不显示，界面与改动前一致。
命中且播放中（isPlaying=true）脉动徽标 + 进度条每秒外推 + 「接下来」+「N 人在听」。
命中但暂停（isPlaying=false）保留标记、停脉动、进度冻在 position（不隐藏，避免闪烁）。
掉线 / 快照过期（>95s 无新快照）移除叠加层，回到原界面。
非当日排期（显示未来最近排期）不叠加任何「正在播放」标记。

五、容错机制

  • 新接口 404/403/超时 → 当「没有广播」处理，绝不影响排期与歌词既有显示。
  • SSE 断开 → 指数退避重连，期间轮询兜底；不进主刷新的网络错误状态机。
  • 轮询失败只记日志，不污染主刷新；快照解析失败保留上一次有效状态。
  • 进度条本地每秒 tick，绝不每秒发请求；服务端 position 自我外推，偶尔快照纠偏。
  • 不升级 ClassIsland.PluginSdk、不引入新 NuGet 依赖；不向 VoiceHub 写任何数据。

六、红线：契约改动必须同步集控侧

红线 一旦改动 /api/songs/public 的路径或字段名，必须同步检查集控侧两个文件（它们各自独立实现了同一份数据契约）：

  • Stelarith-cims-eval\school-multimedia-control\ext\stelarith-classisland-plugin\StelarithSongBoard.cs
  • Stelarith-cims-eval\school-multimedia-control\ext\voicehub-sync\voicehub-adapter.mjs

本次实现未触及既有路径 / 字段，故这两处暂无需改动。同理，集控侧若改契约，本插件也须回查。

八、构建与本地验证

构建

cd D:/Stelarith/Stelarith-voicehub-component
dotnet build -c Release

产出 bin/Release/net8.0-windows/VoiceHubComponent.dll 与 cipx/VoiceHubComponent.cipx。注意：PluginSdk 末步用 pwsh 跑 MD5 校验脚本，本机若无 PowerShell 7 会报 9009，但不影响 DLL / 插件包；用 powershell 手动补跑 generate-md5.ps1 即可。

本地验证

需要一个运行中的 VoiceHub 服务端（广播接口就绪）。启动后，用任一账号开播，再访问以下接口核对字段是否与上方契约一致：

GET /api/music/broadcast        # 轮询快照
GET /api/music/websocket        # SSE，事件 broadcast_state

确认 scheduleId / position / isPlaying / nextUp / listeners 字段齐全后，再在 ClassIsland 端观察大屏叠加层是否按预期出现 / 消失。

九、验收清单

  • 有人在播 → 命中排期出现脉动徽标 + 进度条，进度每秒在走。
  • 停播 → 标记消失，界面回到改动前。
  • 老服务端（不含新字段）→ 界面与改动前一致，无异常日志。
  • 拔网 30 秒 → 不崩、不复位排期，恢复后自动恢复。
  • 播控人暂停 → 标记保留但不脉动。
  • 教室机 CPU 不因新通道明显上升（不每秒请求）。

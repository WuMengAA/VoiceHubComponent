教室大屏「正在播放」实时显示 — 给学生和音乐管理员

一句话 音乐管理员在后台放歌时，教室里的大屏会实时显示「正在播放哪首、播到哪了、下一首是什么、多少人在听」。本功能只显示、不点歌、不切歌、不写任何数据。

给学生你什么都不用操作

大屏由管理员统一控制。你只需要看，不需要点任何按钮。

大屏上你会看到什么

当管理员正在广播、且广播的曲目正好是当前大屏显示的排期曲目时，当前曲目卡片右侧会多出一排实时信息：

  • 脉动绿点 +「正在播放」：此刻正在播放这首（绿点一跳一跳 = 播放中；静止 = 已暂停）。
  • 进度条：这首播到哪了，会自己往前走。
  • 「接下来：XXX」：连播队列里的下一首。
  • 「N 人在听」：当前在线收听的人数。

看不到这些，正常吗？

绝大多数情况：正常，不是坏了 这些元素只在管理员正在广播、且广播的正是当前这张卡片对应的时段时才出现。以下情形都看不到，属于预期：
  • 管理员此刻没有在广播（课间、还没到点）。
  • 广播的是别的时段的曲目，不是当前这张卡片。
  • 当天还没有排期，或当前显示的是「未来最近排期」。
遇到上面这些，不用报修，等广播开始即可。

什么时候需要反馈

  • 大屏显示的歌名 / 进度，和实际听到的长期对不上（偶尔一两秒偏差不算）。
  • 管理员明明在广播，全班大屏却长时间完全不显示。

把现象告诉音乐管理员即可，由管理员排查（见下方管理员篇）。

给管理员开箱即用，一般不用动

插件装好后默认就能用：开关已开、API 地址已填。只在下面两种情况需要你进设置。

要确认的两件事

  1. API 地址填对（设置项 ApiUrl）
    默认是 https://voicehub.lao-shui.top/api/songs/public。如果你们的部署改了域名或路径，要填到能正常拿到排期数据的那个地址。
    关键约束（务必注意） 实时广播通道的域名，是从这个 API 地址自动推导的（取同一来源）。也就是说：排期接口和广播接口必须在同一个域名下。 例：API 地址是 https://voicehub.xxx.com/.../public，广播就会去连 https://voicehub.xxx.com/api/music/websocket。 如果两者跨域 / 跨端口，大屏会收不到实时状态。
  2. 「启用正在播放」开关已打开（设置项 EnableNowPlaying）
    默认开启。只有你想彻底关掉大屏实时显示时才取消勾选。

改动后怎么做

  • 改完点保存，必要时重启 ClassIsland 让设置生效。
  • 怎么确认生效：等有任意一次广播开始，大屏当前卡片出现脉动绿点，就说明链路通了。

大屏不显示实时信息？按这个顺序查

顺序最可能的原因怎么判断 / 处理
1 管理员当前没有在广播 最常见。没广播，大屏本就不显示。先确认后台正在播放。
2 API 地址与广播接口不同域 核对 ApiUrl 的域名，必须和广播接口同一来源（见上方关键约束）。
3 「启用正在播放」开关被关了 进设置确认 EnableNowPlaying 是勾选状态。
4 网络不通 / 服务端不可达 插件会自动重连（间隔 1s→2s→4s…最长 30s），并每 30s 轮询兜底。短暂抖动会自动恢复，不影响主界面。
5 以上都正常但仍异常 查看 ClassIsland 日志里 BroadcastStateClient 相关条目（连接失败 / 轮询失败都有记录），按日志进一步排查。
红线：不要做的事
  • 不要把广播通道和排期接口拆到不同域名——实时状态会全部收不到。
  • 不要把这个插件改成能写数据——它只是广播状态的只读展示，任何点歌 / 切歌的写逻辑都违反设计。
  • 如果要改服务端接口的路径或字段名，必须同步检查集控侧（详见开发者文档的红线一节），否则集控大屏会读不到。
